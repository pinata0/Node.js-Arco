현재 워크벤치의 상태를 점검하고, 이 프로젝트에서 FE/BE 개발환경을 구성하기 전에 필요한 사전 정보를 정리해줘.

## 프로젝트 배경

이 프로젝트는 사용자가 날짜와 관심 분야를 입력하면 해당 날짜에 참석할 수 있는 세미나, 컨퍼런스, 밋업, 해커톤 등의 행사를 추천하는 웹서비스 MVP다.

향후 다음과 같은 구조를 만들 예정이다.

- Frontend: Node.js 기반 프론트엔드
- Backend: Node.js 기반 백엔드
- Database: PostgreSQL
- FE와 BE는 별도 디렉터리로 분리할 예정

이번 단계에서는 환경을 실제로 설치하거나 프로젝트 파일을 생성하지 않는다.

## 이번 작업의 목표

현재 워크벤치와 저장소 상태를 조사해서 다음 단계에서 안전하게 프로젝트 구조와 Node.js 개발환경을 구성할 수 있도록 현재 상태를 보고해줘.

## 확인할 항목

### 1. 현재 저장소 구조

현재 작업 디렉터리를 기준으로 다음을 확인해줘.

- 현재 경로
- Git repository인지 여부
- Git branch
- Git working tree 상태
- 현재 존재하는 주요 파일과 디렉터리
- 기존 `package.json` 존재 여부
- 기존 Node.js 관련 설정 파일 존재 여부
- 기존 FE 또는 BE 코드가 존재하는지
- `.gitignore` 존재 여부
- `.env`, `.env.example` 등 환경변수 관련 파일 존재 여부

전체 파일을 무작정 나열하지 말고 프로젝트 구조를 이해하는 데 필요한 수준으로 정리해줘.

### 2. Node.js 개발환경

다음을 확인해줘.

- Node.js 설치 여부 및 버전
- npm 설치 여부 및 버전
- npx 사용 가능 여부
- 다른 Node 패키지 매니저가 설치되어 있는지
  - pnpm
  - yarn
- 현재 Node.js 버전이 일반적인 최신 개발환경에서 사용하기 적절한지

버전이 없거나 너무 오래되었다면 이후 단계에서 어떤 버전을 사용하는 것이 좋을지 제안만 해줘.

이번 단계에서는 설치하거나 업그레이드하지 마.

### 3. PostgreSQL 관련 환경

다음을 확인해줘.

- PostgreSQL 설치 여부
- `psql` CLI 사용 가능 여부
- PostgreSQL 버전
- 로컬 PostgreSQL 서비스 실행 여부를 확인할 수 있다면 확인
- Docker가 설치되어 있다면 PostgreSQL을 Docker로 실행할 수도 있는 환경인지

이번 단계에서는 PostgreSQL을 설치하거나 실행하지 마.

### 4. 기타 개발 도구

가능하면 다음도 확인해줘.

- Git 버전
- Docker 설치 여부 및 버전
- Docker Compose 사용 가능 여부
- VS Code 또는 현재 개발환경에서 프로젝트 실행에 영향을 줄 만한 설정

### 5. 충돌 가능성

향후 다음 구조를 만들었을 때 기존 파일과 충돌할 가능성이 있는지 확인해줘.

```text
project-root/
├─ frontend/
├─ backend/
├─ .gitignore
└─ README.md
```

특히 기존 프로젝트 파일이 이미 루트에 존재한다면 어떤 파일이 새 구조와 충돌할 수 있는지 알려줘.

## 매우 중요한 제한사항

이번 단계는 **조사 전용**이다.

절대로 다음 작업을 하지 마.

- 파일 생성
- 파일 수정
- 파일 삭제
- 디렉터리 생성
- `npm init`
- `npm install`
- Node.js 설치 또는 업그레이드
- PostgreSQL 설치
- Docker container 생성
- `.gitignore` 수정
- Git commit
- Git checkout 또는 branch 변경
- 기존 설정 자동 수정

명령어는 시스템 상태를 읽고 확인하는 용도로만 사용해줘.
